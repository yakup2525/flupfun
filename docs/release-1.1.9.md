# Flup Fun 1.1.9 (10) startup crash fix

Prepared October 29, 2026. Previous submitted release: 1.1.8 (9). Package: `com.kurtizi.flupfun`.

## Problem and fix

The 1.1.8 release AAB reproduces a fatal startup failure before Flutter starts: `Unable to get provider androidx.startup.InitializationProvider`, caused by `Failed to create an instance of androidx.work.impl.WorkDatabase`. R8 usage output lists the generated `WorkDatabase_Impl` public no-argument constructor as removed; disassembling the AAB-derived APK confirms it has no constructor.

Release Gradle configuration now loads `android/app/proguard-rules.pro`, which preserves the no-argument constructor of Room database subclasses. Shrinking remains enabled. Version advances to 1.1.9 (10); application code, production ad configuration and signing key are unchanged.

## Validation

- `flutter analyze`: no issues.
- `flutter test`: all seven existing tests pass.
- `scripts/build_android_release.sh`: signed release AAB builds successfully.
- `bundletool validate`: passes; `jarsigner -verify`: jar verified.
- R8 configuration includes the custom constructor rule; seeds retain `WorkDatabase_Impl()` and usage no longer lists it as removed.
- DEX from the final AAB-derived universal APK contains `.method public constructor <init>()V` on `androidx.work.impl.WorkDatabase_Impl`.
- Final AAB-derived universal APK installed and launched on emulator-5554 (4096-byte pages) and emulator-5556 (16384-byte pages). Both display the Flutter TAP TO PLAY screen and remain alive after starting a round. App-specific logs contain no startup exception. The emulators produce unrelated Google Play Services crashes, excluded from the app logs.
- Universal test APK uses the local debug certificate generated by bundletool; the release AAB uses the existing upload certificate. This does not constitute a Google Play installed-build test.
- Manifest identifies package `com.kurtizi.flupfun`, version 1.1.9 (10) and the existing production AdMob App ID; AD_ID/AdServices permissions remain absent.
